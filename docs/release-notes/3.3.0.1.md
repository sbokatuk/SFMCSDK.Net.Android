## What's changed

Moves the binding to the current Salesforce release. Nothing is removed and no existing
signature changes, so for an app that calls the SDK this is a version bump.

- Binds **sfmcsdk 3.3.0** (was 3.1.1) and ships **`common-internal` 1.1.0** (was 1.0.0)
  alongside it, both resolved from Salesforce's own Maven repository and SHA-256-pinned on every
  build. sfmcsdk 3.2.0 was never released as a package; its changes arrive with this one.
- Unchanged: the target frameworks (`net8.0-android34.0`, `net9.0-android35.0`,
  `net10.0-android36.0`), the Android 8.0 (API 26) floor, the permissions and components the
  `.aar` adds to your manifest, and every NuGet dependency version - the 3.3.0 `.pom` names the
  same Kotlin, AndroidX and Play services versions as 3.1.1.
- New API, all of it additive. Salesforce publishes no release notes for these versions, so the
  list comes from comparing the classes of the two `.aar` files:
  - the plug-in point for the new MobilePush inbox module -
    `SFMCSdkModuleConfig.InboxFeatureModuleConfig` and the matching `Builder` property, the
    abstract `Modules.Inboxfeature.InboxFeatureModuleConfig`, `ModuleIdentifier.InboxFeatureModule`,
    `Event.Producer.InboxFeatureModule`, `ModuleLogger.Inbox`, `SdkLogger.Inbox`, `InboxLogger`
    and `BuildConfig.InboxFeatureModuleApplicationId`;
  - `IImageCacheApi.Evict(ICollection<string>)`, from 3.2.0;
  - `IApplicationLifecycleStateProvider`, with `IsApplicationForegrounded`;
  - the constant `NetworkManager.Redacted`, from 3.2.0;
  - `SFMCSdk.SdkVersionName` and `BuildConfig.VersionName` now read `3.3.0`.
- The inbox itself is **not** in this package. It is the `inboxfeaturemodule` and
  `inboxmodelsmodule` artifacts, which belong to MobilePush and therefore to
  [MarketingCloudSDK.Net.Android](https://github.com/sbokatuk/MarketingCloudSDK.Net.Android);
  sfmcsdk only declares where they plug in.
- One source and binary break, and only for code that implements `IImageCacheApi` itself: the
  interface gained `Evict`, so such a class must add it and be recompiled. Code that calls the
  SDK is unaffected.
- `common-internal` 1.1.0 is a real requirement this time, not a formality: sfmcsdk 3.3.0 calls
  classes that 1.0.0 does not contain, and an app carrying the old one is killed at launch with
  `NoClassDefFoundError`. It still ships inside this package, so there is nothing to add - and,
  as before, no other package may ship it as well.
- Using MobilePush? The published MarketingCloudSDK.Net.Android 11.0.1.x packages were built
  and tested on sfmcsdk 3.1.1, and this release has not been tested beneath them. sfmcsdk 3.3.0
  is the core that the native marketingcloudsdk 12.0.0 requires; stay on 3.1.1.1 until you move
  to the MobilePush package for that line.
- Using the [SFMCSDK.Net](https://www.nuget.org/packages/SFMCSDK.Net) umbrella? Its current
  release, 4.0.1.2, depends on SFMCSDK.Net.Android at exactly `[3.1.1.1]` on all three Android
  target frameworks, so an app that takes the core through the umbrella cannot move to this
  package until an umbrella release re-pins it.
- Verified on an Android 15 (API 35) emulator: the device checks on `net8.0-android34.0`,
  `net10.0-android36.0` and an R8-shrunk `net10.0-android36.0` build, and the MAUI sample
  through initialisation, setting a profile id and tracking a custom event. The device checks
  now also assert that the `.aar` inside the package is the version the binding was generated
  from, and that `common-internal` is new enough for it.
